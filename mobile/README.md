## ۱) چه چیزی ساخته شد؟

یک پروژهٔ **کاملاً مستقل** در پوشهٔ `mobile/` کنار پروژهٔ اصلی:

```
mobile/
├─ web/                     رابط کاربری (تنها منبع حقیقت)
│  ├─ index.html            پوستهٔ اپ + اسپلش + onboarding
│  ├─ app.css               دیزاین‌سیستم (تم تاریک/روشن، RTL، فونت وزیرمتن)
│  ├─ manifest.webmanifest  نصب به‌عنوان PWA در مرورگر
│  ├─ assets/               آیکون‌ها + فونت وزیرمتن (woff2)
│  └─ js/
│     ├─ core/              ابزارها، قالب‌بندی، آیکون‌ها، نمودار، آداپتر API، موتور دمو، کلاینت پنل، استور
│     ├─ ui/                پوسته (تب‌بار، شیت، مودال، توست)، ویجت‌ها، onboarding
│     ├─ tabs/              ۱۰ بخش مستقل
│     └─ app.js             راه‌اندازی
├─ android/                 پروژهٔ Gradle + پوستهٔ WebView + پل نیتیو
├─ tools/                   ساخت آیکون، سینک assets
├─ tests/                   تست دود UI (jsdom) + سرور پیش‌نمایش
├─ scripts/                 ساخت APK با یک دستور (لینوکس/مک و ویندوز)
└─ docs/                    راهنمای ساخت، نگاشت API، عیب‌یابی
```

> رابط `web/` هیچ وابستگی بیرونی ندارد (بدون React/Vue/Tailwind) و در زمان ساخت
> به‌صورت خودکار داخل APK کپی می‌شود؛ بنابراین همان کد هم در مرورگر و هم در اندروید اجرا می‌شود.

## ۳) اجرا در مرورگر (بدون اندروید)

```bash
cd mobile
node tests/serve.js 8080          # یا: npm run serve
# مرورگر: http://127.0.0.1:8080
```

برای دیدن از گوشی، سرور روی `0.0.0.0` بالا می‌آید؛ آدرس `http://IP-کامپیوتر:8080` را باز کنید.
هزینهٔ اجرا: یک فایل HTML + چند فایل JS/CSS/فونت؛ بدون build step.

> در مرورگر، اتصال به پنل باید با CORS مجاز باشد. در نسخهٔ اندروید این محدودیت وجود ندارد
> چون درخواست‌ها از پل نیتیو رد می‌شوند.

## ۴) ساخت APK

### الف) با GitHub Actions (بدون نصب چیزی)

پس از push، گردش‌کار `Android Mobile APK` در ریشهٔ مخزن اجرا می‌شود:

* **Actions → Android Mobile APK → Run workflow** را بزنید،
* در پایان، از بخش **Artifacts** فایل `X28Mobile-apk` را دانلود کنید،
* برای انتشار خودکار: تگ `v1.0.0` بزنید تا APK به Release همان تگ ضمیمه شود.

### ب) روی سیستم خودتان

پیش‌نیازها: **JDK 17**، **Android SDK Platform 34** و Build-Tools (نصب از Android Studio)، و اختیاری Node.js 18+.

```bash
cd mobile
export ANDROID_HOME=$HOME/Android/Sdk
bash scripts/build_apk.sh            # → dist/X28Mobile-YYYYMMDD-debug.apk
```

در ویندوز:

```bat
cd mobile
scripts\build_apk.bat
```

نصب روی گوشی:

```bash
adb install -r dist/X28Mobile-*.apk
```

یا فایل APK را به گوشی منتقل کنید و «نصب از منابع نامشخص» را برای فایل‌منیجر اجازه دهید.

جزئیات کامل ساخت، امضا و انتشار: [`docs/BUILD_APK_FA.md`](docs/BUILD_APK_FA.md)

## ۵) اتصال به پنل X28

1. پنل را روی کامپیوتر اجرا کنید و آن را برای شبکه باز کنید:

   ```bash
   python app.py --host 0.0.0.0 --port 8080
   ```

2. در برنامه → **تنظیمات → اتصال → اتصال به پنل**:
   * **آدرس پنل:** `http://192.168.1.10:8080` (IP کامپیوتر، نه `127.0.0.1`)
   * **توکن عملیات:** اگر در `config.json` مقدار `security.action_token` گذاشته‌اید
   * **رمز ورود:** اگر `security.password` تنظیم شده است
3. **اتصال و تست** را بزنید. اگر موفق باشد، نشانگر بالای برنامه «پنل متصل» می‌شود و
   داده‌ها هر ۲.۵ ثانیه به‌روز می‌شوند.

اگر پنل روی HTTPS با گواهی خودامضا اجرا می‌شود، برنامه گواهی را نادیده نمی‌گیرد
(برای امنیت بیشتر)؛ از `http://` در شبکهٔ محلی استفاده کنید یا گواهی معتبر بدهید.

### نگاشت داده‌ها

فایل [`web/js/core/adapt.js`](web/js/core/adapt.js) پاسخ `/api/status` را «صاف» می‌کند و با
فهرستی از نام‌های رایج (مثل `rsrp`, `lte_rsrp`, `signal.rsrp`) مقدار را پیدا می‌کند.
اگر فریم‌ور/پنل شما نام دیگری دارد، همان‌جا اضافه کنید — نیازی به تغییر سایر بخش‌ها نیست.
راهنمای کامل: [`docs/API_MAPPING_FA.md`](docs/API_MAPPING_FA.md)

از **شبکه → پاسخ خام پنل** می‌توانید JSON واقعی را ببینید و کلید درست را پیدا کنید.

## ۶) حالت نمایشی (Demo)

حالت پیش‌فرض پس از نصب، «نمایشی» است تا بدون مودم همه چیز قابل بررسی باشد:

* ۲۴ ساعت تاریخچهٔ واقع‌نما (تأخیر، ترافیک، RSRP/SINR، تعداد کلاینت)،
* ۸ دستگاه نمونه با ترافیک متغیر،
* تغییر باند توسط شبکه، افت سیگنال، قطعی، رویدادها و هشدارها،
* آزمون سرعت با نوار پیشرفت واقعی،
* اجرای همهٔ عملیات (قفل باند، ریبوت، APN، WPS…) با نتیجهٔ شبیه‌سازی‌شده.

ابزارهای شبیه‌سازی در **تنظیمات → ابزار شبیه‌سازی**: قطعی ۳۰ ثانیه‌ای، رویداد هشدار،
افزودن دستگاه آزمایشی و بازسازی تاریخچه.

## ۷) معماری

```
┌──────────────────────────── WebView (assets/web) ────────────────────────────┐
│  app.js → store (state) ← demo engine  |  device client ← adapt.js           │
│         ↓ subscribe                                                          │
│  shell (tabbar / sheet / modal / toast) → tabs/*.js (۱۰ بخش)                 │
│         charts.js (canvas)   widgets.js   onboarding.js                       │
└───────────────▲──────────────────────────────────────────────────────────────┘
                │ window.Android.http(...)  (JSON in/out)
┌───────────────┴──────────────────────────────────────────────────────────────┐
│ NativeBridge.java: HttpURLConnection + کوکی + ذخیرهٔ فایل + اشتراک + لرزش      │
│ MainActivity.java: WebViewAssetLoader (origin امن)، دکمهٔ Back، نوار وضعیت     │
└──────────────────────────────────────────────────────────────────────────────┘
```

* **بدون CORS و بدون مشکل HTTP در Android 9+**: درخواست‌ها نیتیو هستند
  (`usesCleartextTraffic` + `network_security_config`).
* **Origin امن**: UI از `https://appassets.androidplatform.net/assets/web/…` سرو می‌شود،
  پس `localStorage` و فونت‌ها بدون ترفند کار می‌کنند.
* **دکمهٔ Back**: اول شیت/مودال، بعد بازگشت به داشبورد، بعد خروج با تأیید دوباره.
* **بدون ترکینگ**: هیچ درخواستی به بیرون از شبکهٔ شما زده نمی‌شود.

## ۱۱) وضعیت و قدم‌های بعدی

**انجام‌شده:** ۱۰ بخش کامل، حالت نمایشی، آداپتر API مقاوم، پل نیتیو (HTTP/کوکی/اشتراک/ذخیره/لرزش/روشن‌ماندن صفحه)،
تم تاریک و روشن، RTL و وزیرمتن، آزمون دود، ساخت APK با یک دستور، گردش‌کار GitHub Actions، آیکون‌ها و اسپلش.

**پیشنهاد برای ادامه:**

1. Push/Release: تگ بزنید تا APK از Actions به Release ضمیمه شود.
2. اگر پنل را تغییر دادید، فقط `adapt.js` را به‌روز کنید (نه کل رابط).
3. اعلان‌های اندروید (Foreground Service) برای هشدارهای آستانه‌ای.
4. ویجت صفحهٔ اصلی (App Widget) برای RSRP/سرعت.
5. جداسازی به مخزن مستقل `x28panel-mobile` در صورت نیاز (پوشهٔ `mobile/` خودکفاست).
