# X28 Control Center

پنل مستقل، زنده و قابل‌توسعه برای مدیریت و پایش مودم **X28 (ZLT)** — بدون دست‌زدن به فریم‌ور مودم.

> نسخهٔ ۲ برنامهٔ `modem_panel.py` شما: همان منابع داده (پینگ، SNMP، SSH/Telnet، وب‌API، TR-069)
> در حالت نمونه/دمو، پلاگین `mock` روشن می‌شود تا داشبورد زنده بماند؛ با اتصال مودم واقعی می‌توانید خاموشش کنید.

> به‌علاوهٔ موتور پلاگین، داشبورد زنده، دیتابیس تاریخی، خوانندهٔ لاگ رویداد، اتوماسیون هشدار و دو تم ظاهری (تاریک/روشن).

---

## ۱) نصب و اجرا

```bash
cd x28-panel
pip install -r requirements.txt          # flask + requests (paramiko فقط اگر SSH می‌خواهید)

cp config.example.json config.json       # ویندوز: copy config.example.json config.json
#   config.json را باز کنید و آدرس/کاربر/رمز مودم را بگذارید

python app.py                            # سپس مرورگر: http://127.0.0.1:8080
```

تنظیم رمزها بدون گذاشتن در فایل (توصیه‌شده):

```bash
# لینوکس/مک
export MODEM_PASS='رمز-پنل-مودم'
export PANEL_TOKEN='یک-توکن-قوی'
export TG_TOKEN='توکن-ربات-تلگرام'

# ویندوز (PowerShell)
$env:MODEM_PASS='رمز-پنل-مودم'
```

دستورهای کمکی:

```bash
python app.py --list-plugins                    # فهرست پلاگین‌ها و بازهٔ اجرایشان
python app.py --import-log path/to/log          # ورود لاگ رویداد مودم (متن، gzip یا فایل مخدوش)
python tools/import_log.py path/to/log          # همان کار به‌صورت ابزار مستقل
```

## ۲) معماری (چرا قابل توسعه است)

```
app.py                نقطهٔ شروع: وب‌سرور + مونتاژ هسته
core/                 هسته: config, bus (گذرگاه زنده), store (SQLite),
                      registry (موتور پلاگین), scheduler (زمان‌بند + هشدار), api (REST + SSE), auth
drivers/zlt_web.py    درایور پنل وب مودم X28 (ورود، خواندن وضعیت، قفل باند، APN، ریبوت…)
plugins/*.py          هر فایل = یک قابلیت مستقل (خودش را در UI معرفی می‌کند)
ui/                   رابط کاربری بدون کتابخانهٔ بیرونی: index.html + app.js + style.css
data/                 دیتابیس، بکاپ‌ها و پاسخ‌های خام مودم
```

هسته هیچ‌وقت تغییر نمی‌کند وقتی قابلیت جدید اضافه می‌شود.

### پلاگین‌های همراه

| پلاگین | کار | پیش‌فرض |
|---|---|---|
| `ping` | آنلاین/آفلاین، تأخیر، افت بسته، jitter (با جایگزین TCP اگر ICMP مسدود باشد) | روشن |
| `snmp` | ترافیک WAN، آپ‌تایم، نام سیستم (پیاده‌سازی BER خالص پایتون) | روشن |
| `bandwatch` | نگهبان باند و سلول: هشدار ناپایداری باند، هشدار ضعف سیگنال، اعمال خودکار پروفایل در بازهٔ خلوت | روشن |
| `speed` | آزمون سرعت (دانلود/آپلود/تأخیر) با ذخیرهٔ نتیجه در تاریخچه برای مقایسهٔ باندها | دستی |
| `netinfo` | تشخیص شبکه برای تب «شبکه و APN»: IP عمومی و CGNAT، سنجش DNS، پینگ TCP، روزهای گواهی TLS، هشدار تغییر IP/قطع اتصال | روشن |
| `mock` | شبیه‌ساز (دمو): اگر مودم واقعی پاسخ ندهد، دادهٔ نمونهٔ زنده می‌سازد تا نمودارها خالی نمانند (فقط جاهای خالی را پر می‌کند و هر عدد واقعی را کنار می‌زند) | خاموش* |
| `zlt` | **کنترل مودم**: ورود به پنل، سیگنال/باند، قفل باند، حالت شبکه، APN، ریبوت، اسکن، Wi-Fi | روشن |
| `logwatch` | خواندن `web_event_super.log`، ذخیرهٔ رویدادها، هشدار روی رخدادهای حساس | روشن |
| `ssh` | اجرای دستور روی مودم با SSH/Telnet + ریبوت | خاموش |
| `tr069` | خواندن پارامترها از GenieACS | خاموش |
| `telegram` | ارسال هشدارها به تلگرام (نوتیفایر) | خاموش |
| `ai` | دستیار هوشمند: تحلیل وضعیت و پیشنهاد فارسی (حالت آفلاین یا با کلید API) | خاموش |
| `devwatch` | رصد دستگاه‌های شبکه: نوع دستگاه (موبایل/تبلت/لپ‌تاپ/…) و پهنای باند لحظهٔ هر دستگاه (تب ۵) | روشن |

## ۳) افزودن قابلیت جدید (قرارداد پلاگین)

یک فایل در `plugins/` بسازید و قرارداد را رعایت کنید؛ همین. پنل خودش پلاگین را پیدا می‌کند،
فرم تنظیماتش را در UI می‌سازد و عملیاتش را در صفحهٔ «کنترل مودم» می‌گذارد.

```python
META = {
    "id": "my_plugin", "name": "پلاگین من", "icon": "★",
    "description": "چه کاری می‌کند",
    "kind": "monitor",          # monitor | notifier | assistant
    "interval": 30,             # ثانیه
    "enabled": True,
    "emits": ["my_metric"],     # مقادیری که برای نمودار ذخیره می‌شوند
    "config_schema": [
        {"key": "url", "label": "آدرس", "type": "str", "default": "http://...", "help": "توضیح"},
    ],
}

def collect(ctx):                        # داده‌های تازه (اجباری)
    return {"my_metric": 42}

def actions():                           # عملیات قابل اجرا در UI (اختیاری)
    return [{"name": "my_do", "label": "انجام بده", "plugin": "my_plugin",
             "danger": False, "params": [{"key": "x", "label": "پارامتر", "type": "str", "default": ""}]}]

def run_action(ctx, name, params):       # اجرای عملیات
    ctx.emit("my action", "done")        # ثبت در فید زنده + دیتابیس
    return {"ok": True, "message": "انجام شد"}
```

امکاناتی که `ctx` در اختیار پلاگین می‌گذارد:
`ctx.conf` تنظیمات پلاگین · `ctx.modem()` مشخصات مودم فعلی · `ctx.secret('env:X')` خواندن رمز از محیط ·
`ctx.store` دیتابیس (رویداد/نمونه/پروفایل/بکاپ) · `ctx.hub` وضعیت همهٔ پلاگین‌ها · `ctx.kv` حافظهٔ خصوصی ·
`ctx.emit()` ثبت رویداد · `ctx.alert()` هشدار (به تلگرام هم می‌رود) · `ctx.note()` پیام وضعیت در UI.

نمونهٔ کامل و واقعی: `plugins/snmp.py` (پایش) و `plugins/zlt.py` (پایش + ۹ عملیات).

## ۴) رابط برنامه (API)

| متد | مسیر | کار |
|---|---|---|
| GET | `/api/status` | وضعیت لحظه‌ای همهٔ منابع + سیگنال + سلامت |
| GET | `/api/stream` | کانال زندهٔ SSE (UI همین را می‌خواند) |
| GET | `/api/series?keys=snmp.rx_bps&range=1h` | تاریخچه (1m…30d) |
| GET | `/api/events?q=&category=&limit=` | جست‌وجو در رویدادها + دسته‌بندی + هیستوگرام ساعتی |
| POST | `/api/import-log` | ورود فایل لاگ (متن/gzip/مخدوش) |
| GET | `/api/actions` · POST `/api/action/<name>` | فهرست و اجرای عملیات |
| GET | `/api/plugins` · POST `/api/plugins/<id>` · POST `/api/plugins-reload` | مدیریت پلاگین‌ها در زمان اجرا |
| GET/POST | `/api/config` | خواندن/نوشتن تنظیمات مجاز (نام، تم، مودم‌ها، آستانه‌ها) |
| GET | `/api/audit` | گزارش عملیات و هشدارها |

عملیات حساس با هدر `X-Token` یا نشست ورود محافظت می‌شوند.

## ۵) امنیت (M4)

- پیش‌فرض فقط روی `127.0.0.1` گوش می‌دهد. برای شبکهٔ محلی `listen_host` را `0.0.0.0` کنید و پشت فایروال بمانید.
- برای ورود با رمز: در `config.json` مقدار `security.password` را بگذارید (بهتر: `env:PANEL_PASS`).
  بعد از آن، همهٔ APIها نشست لازم دارند (کوکی httponly + انقضا).
- رمز مودم/توکن‌ها را `env:NAME` بنویسید تا داخل فایل ذخیره نشوند.
- همهٔ عملیات با IP و زمان در جدول `actions` ثبت می‌شود (Audit).
- عملیات حساس (قفل باند، ریبوت، تغییر APN/Wi-Fi) قبل از اجرا خودکار بکاپ پیکربندی می‌گیرند.

## ۶) نکتهٔ کلیدی دربارهٔ کنترل مودم

مسیرهای داخلی پنل وب X28 بین نسخه‌های فریم‌ور فرق می‌کند؛ پس هیچ‌چیز هاردکد نشده.
دو راه دارید:

1. **تشخیص خودکار:** در پنل → «کنترل مودم» → عملیات «تشخیص خودکار پنل مودم».
2. **استخراج دقیق (۲ دقیقه):** راهنمای `docs/CAPTURE_GUIDE.md` — یک بار در پنل خود مودم کار موردنظر
   (مثلاً قفل باند) را انجام می‌دهید، درخواستش را از DevTools کپی می‌کنید و در تنظیمات پلاگین `zlt` می‌گذارید.

پاسخ‌های خام مودم در `data/raw/` ذخیره می‌شوند؛ اگر چیزی خوانده نشد، همان فایل‌ها را بفرستید تا نگاشت را دقیق کنم.

## ۵٫۵) خروجی EXE (ویندوز) — ساخته شد

```text
release/X28Panel-Windows-x64.zip     ← بستهٔ آمادهٔ تحویل (۱۵٫۹MB، ۱۲۷ فایل)
  X28Panel/X28Panel.exe              ← دوبار کلیک؛ خودش مرورگر را باز می‌کند (127.0.0.1:8080)
  X28Panel/X28Panel-console.exe      ← برای --setup، --paths، --discover و عیب‌یابی
  X28Panel/README-FIRST.txt          ← راهنمای کوتاه فارسی برای کاربر نهایی
  X28Panel/_internal/…               ← ui/ · plugins/ · drivers/ · docs/ · فونت وزیرمتن
```

**اجرای اول:** پنل بدون مودم ساخته می‌شود و همان سه سؤال را می‌پرسد (آدرس پنل ادمین مودم،
نام کاربری ادمین، رمز ادمین مودم) و بعد خودش مودم را می‌شناسد و لاگ رویداد را می‌خواند.

**رمز ورود پنل؟** در اجرای اول **ندارد (خالی)** — پنل بدون رمز و فقط روی `127.0.0.1` باز می‌شود.
برای گذاشتن رمز: تب ۱۰ → «دسترسی و امنیت» → «رمز ورود پنل». برای برداشتنش:
`security.password` را در `config.json` خالی کنید. هیچ رمز پیش‌فرض ثابتی در بسته نیست.

ساخت مجدد روی ویندوز: `packaging\build_windows.bat` (حالت پیش‌فرض = کامل با SSH؛
با `set X28_LEAN=1` = سبک‌تر و بدون SSH). جزئیات: `docs/EXE_FA.md`.
